# Automatic updates

The chart updates itself when your data changes: when items are added to, removed from or replaced in a collection,
when a property of a point changes, and when a property of a series, an axis or the chart changes. It finds out
through the `INotifyCollectionChanged` and `INotifyPropertyChanged` interfaces of .NET, so the chart sees a change
only when the object that changed implements one of them. This article shows what the chart listens to, how to change
the data from other threads, how to build a real time chart and how to show or hide series.

:::info
Every property is listed in the API explorer:
[CartesianChart]({{ website_url }}/api/{{ version }}/LiveChartsCore.SkiaSharpView.{{ platform }}.CartesianChart),
[ObservableValue]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ObservableValue),
[ObservablePoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ObservablePoint) and
[ChartUpdateParams]({{ website_url }}/api/{{ version }}/LiveChartsCore.Kernel.ChartUpdateParams).
{{~ if xaml ~}}
In XAML, the samples declare the series as `XamlLineSeries` and `XamlColumnSeries`, and name them with `SeriesName`.
{{~ end ~}}
:::

## Collections

The chart listens to the `CollectionChanged` event of collections that implement `INotifyCollectionChanged`, such as
`ObservableCollection<T>`. Use one for the `Values` of a series and the chart updates when you add, insert, remove,
replace, move or clear items. Use one for the `Series` of the chart and it updates when you add or remove series.

This sample adds, replaces and removes points of the first series, and adds and removes series.
{{~ if xaml ~}}
The series come from `SeriesSource`: every item of the `Data` collection becomes a series built from
`SeriesTemplate`, so adding an item to `Data` adds a series and removing the item removes the series.
{{~ end ~}}

{{ render_sample "lines/autoupdate" }}

A `List<T>` or an array does not notify changes, so the chart does not see the items you add to it later:

```csharp
// ObservableCollection<T> notifies every change
var values = new ObservableCollection<double> { 4, 6 };
var lineSeries = new LineSeries<double> { Values = values };

values.Add(2); // the chart updates // mark

// List<T> does not notify changes
var list = new List<double> { 4, 6 };
var lineSeries2 = new LineSeries<double> { Values = list };

list.Add(2); // the chart does not update
```

The same applies to the `Series` property of the chart:

```csharp
// bind or assign the chart's Series to this collection
public ObservableCollection<ISeries> Series { get; } = new ObservableCollection<ISeries>();

public void AddSeries()
{
    // the chart updates
    Series.Add(new LineSeries<double> { Values = new double[] { 1, 2, 3 } }); // mark
}
```

## Observable points

To see a change in the value of a point, the point must implement `INotifyPropertyChanged`. The series subscribes to
the `PropertyChanged` event of every point in `Values` and updates the chart when it is raised. The point types in
`LiveChartsCore.Defaults`, such as `ObservableValue`, `ObservablePoint`, `DateTimePoint`, `TimeSpanPoint`,
`WeightedPoint` and `FinancialPoint`, implement it.

```csharp
var values = new ObservableCollection<ObservableValue>
{
    new(1),
    new(2),
    new(3)
};

var lineSeries = new LineSeries<ObservableValue> { Values = values };

values[0].Value = 5; // the chart updates // mark
```

This also works when `Values` is a `List<T>` or an array: the series subscribes to the points it holds when you
assign it. Only the points added later go unnoticed, because the list does not notify that they were added.

Your own types work the same way: implement `INotifyPropertyChanged` and tell the chart how to plot them with a
[mapper]({{ website_url }}/docs/{{ platform }}/{{ version }}/Overview.Mappers). The point must be a class, a struct
that implements `INotifyPropertyChanged` is not tracked. When the points are a value type, such as `double`, the series
only listens to the collection.

```csharp
using System.ComponentModel;
using System.Runtime.CompilerServices;

public class City : INotifyPropertyChanged
{
    private double _population;

    public double Population
    {
        get => _population;
        set { _population = value; OnPropertyChanged(); } // mark
    }

    public event PropertyChangedEventHandler? PropertyChanged;

    protected void OnPropertyChanged([CallerMemberName] string? propertyName = null) =>
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
}
```

```csharp
var cities = new ObservableCollection<City>
{
    new() { Population = 100 },
    new() { Population = 200 },
    new() { Population = 300 }
};

var columnSeries = new ColumnSeries<City>
{
    Values = cities,
    Mapping = (city, index) => new(index, city.Population)
};

cities[0].Population = 500; // the chart updates // mark
```

Without `INotifyPropertyChanged`, the chart is not told that `Population` changed.

## Replace values or series

Assigning a new collection to `Values`, or to the `Series` of the chart, always updates the chart, whatever the type
of the collection. The chart stops listening to the old collection and starts listening to the new one.

Series, axes, sections and visual elements implement `INotifyPropertyChanged` too, and the chart listens to them, so
changing a property such as the `Name`, `Stroke` or `IsVisible` of a series, or the `MinLimit` of an axis, also
updates the chart. Most properties of the chart control do the same.

## Throttling and manual updates

The chart does not update once per change. After a change it waits `UpdaterThrottler`, 50 milliseconds by default,
and then draws every change made in that time in one update. To change the default for every chart, set it before the
charts are created:

```csharp
LiveCharts.Configure(config =>
    config.WithUpdateThrottlingTimeout(TimeSpan.FromMilliseconds(100))); // mark
```

`AutoUpdateEnabled` is `true` by default. When it is `false`, the chart ignores every change above, and you update it
yourself:

```csharp
cartesianChart.AutoUpdateEnabled = false;

// ... change the data, then:
cartesianChart.CoreChart.Update(new ChartUpdateParams { IsAutomaticUpdate = false }); // mark
```

`Throttling = false` in `ChartUpdateParams` starts the update without waiting `UpdaterThrottler`. See the
[animations article]({{ website_url }}/docs/{{ platform }}/{{ version }}/Overview.Animations) for how
`UpdaterThrottler` and the animations work together when the data changes fast.

## Multiple threads

You can change the data from any thread, but the chart measures on the UI thread and reads your collections while it
does. If another thread changes a collection at the same time, the update can fail with an
`InvalidOperationException` (collection was modified) or read data that is half changed; the chart catches the error
and writes it to `Trace`. There are two ways to prevent it.

The first one is to wrap every change in a `lock`, and give the chart the same object in its `SyncContext` property.
The chart takes that lock while it measures and while it draws a frame, so your changes and the chart never run at the
same time. By default, every chart creates its own `SyncContext` object.

This sample starts with 1500 points and runs 10 tasks. Each task adds a point and removes the first one in a loop,
waiting 1 millisecond between changes, inside a `lock`, and the `SyncContext` of the chart is the object they lock.
The chart draws all the changes made during each `UpdaterThrottler` interval in one update.

{{ render_sample "general/multiThreading" }}

The parts that matter are the lock and the `SyncContext`:

```csharp
public object Sync { get; } = new object();

// on any thread
lock (Sync) // mark
{
    Values.Add(newValue);
    Values.RemoveAt(0);
}
```

{{~ if xaml ~}}
```xml
<lvc:CartesianChart
    SyncContext="{Binding Sync}"><!-- mark -->
</lvc:CartesianChart>
```
{{~ end ~}}

{{~ if blazor ~}}
```xml
<CartesianChart
    Series="@series"
    SyncContext="@sync"><!-- mark -->
</CartesianChart>
```
{{~ end ~}}

{{~ if winforms || eto ~}}
```csharp
cartesianChart.SyncContext = sync;
```
{{~ end ~}}

Keep the code inside the lock short, the chart waits for it before it measures or draws a frame. When several charts
show the same data, set the same object in the `SyncContext` of each of them.

The second way is to make the changes on the UI thread, where the chart measures. No lock is needed, but the UI thread
does the work of every change:

```csharp
// on a background thread
InvokeOnUIThread(() =>
{
    Values.Add(newValue);
    Values.RemoveAt(0);
});
```

{{~ if wpf ~}}
`InvokeOnUIThread` runs the action with `Dispatcher.Invoke(action)`.
{{~ end ~}}
{{~ if avalonia ~}}
`InvokeOnUIThread` runs the action with `Dispatcher.UIThread.Post(action)`.
{{~ end ~}}
{{~ if maui ~}}
`InvokeOnUIThread` runs the action with `MainThread.BeginInvokeOnMainThread(action)`.
{{~ end ~}}
{{~ if winui || uno ~}}
`InvokeOnUIThread` runs the action with `DispatcherQueue.TryEnqueue(() => action())`.
{{~ end ~}}
{{~ if winforms ~}}
`InvokeOnUIThread` runs the action with `BeginInvoke(action)`.
{{~ end ~}}
{{~ if eto ~}}
`InvokeOnUIThread` runs the action with `Application.Instance.InvokeAsync(action)`.
{{~ end ~}}
{{~ if blazor ~}}
`InvokeOnUIThread` runs the action with the `InvokeAsync(action)` method of the component.
{{~ end ~}}

The `General/MultiThreading2` sample in the
[samples folder](https://github.com/beto-rodriguez/LiveCharts2/tree/master/samples) does it this way.

## Real time charts

A real time chart shows a moving window of data: add each new point at the end of the collection and remove the
oldest one, so the collection keeps the same size. The axis limits follow the data, so the window moves.

This sample adds a `DateTimePoint` every 100 milliseconds and removes the first point when there are more than 250.
Each time, it also sets the `CustomSeparators` of the X axis to a separator every 5 seconds counting back from now,
and the labels show how many seconds ago each separator was. The X axis sets `AnimationsSpeed` to `0`, so the
separators and labels move without an animation. The changes are made inside a `lock`{{ if !winforms && !eto }}, and
the chart's `SyncContext` is the object they lock, as in the previous section{{ end }}. See
[time and logarithmic scales]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Time%20and%20logarithmic%20scales)
for more about date axes.

## Show or hide series

`IsVisible` shows or hides a series, it is `true` by default, and changing it updates the chart. A hidden series does not count for the axis limits and its points are not hovered; in this sample the
visible columns take the space of the hidden one.
{{~ if xaml ~}}
The series are built from `SeriesSource`, and each one binds `IsVisible` to its item in the view model.
{{~ end ~}}

{{ render_sample "general/visibility" }}

A hidden series stays in the legend, set `IsVisibleAtLegend` to `false` to remove it from the legend too. The chart
keeps processing a hidden series on every update, so it can animate the series when it is hidden or shown again; when
a series will not be shown again, remove it from `Series` instead.
