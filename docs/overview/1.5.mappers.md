# Mappers

Every value in a series becomes a `Coordinate`, the position of the point in the chart. LiveCharts already knows how
to build the coordinate of numbers and of the types in the `LiveChartsCore.Defaults` namespace. To plot your own
types, give LiveCharts a mapper, a function that returns the coordinate of each value, or implement `IChartEntity` in
your type. This article covers both, the `Coordinate` struct, empty points, and how to customize the visual of each
point.

:::info
Every member is listed in the API explorer:
[Coordinate]({{ website_url }}/api/{{ version }}/LiveChartsCore.Kernel.Coordinate),
[IChartEntity]({{ website_url }}/api/{{ version }}/LiveChartsCore.Kernel.IChartEntity),
[LiveChartsSettings]({{ website_url }}/api/{{ version }}/LiveChartsCore.Kernel.LiveChartsSettings) and

## Built-in types

These types work without a mapper. The X of a plain number is its position in the `Values` collection (its index),
and its Y is the value. The other types in this table implement `IChartEntity` and `INotifyPropertyChanged`, so the
chart updates when one of their properties changes, see
[automatic updates]({{ website_url }}/docs/{{ platform }}/{{ version }}/Overview.Automatic%20updates).

| Type | Coordinate | Used by |
|---|---|---|
| `short`, `int`, `long`, `float`, `double`, `decimal` and their nullable versions | X = index, Y = the value | most series |
| [ObservableValue]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ObservableValue) | X = index, Y = `Value` | most series |
| [ObservablePoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ObservablePoint) | X = `X`, Y = `Y` | Cartesian series |
| [DateTimePoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.DateTimePoint) | X = `DateTime.Ticks`, Y = `Value` | Cartesian series |
| [TimeSpanPoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.TimeSpanPoint) | X = `TimeSpan.Ticks`, Y = `Value` | Cartesian series |
| [WeightedPoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.WeightedPoint) | X = `X`, Y = `Y`, weight = `Weight` | bubble and heat series |
| [ObservablePolarPoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ObservablePolarPoint) | X = `Angle`, Y = `Radius` | polar series |
| [FinancialPoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.FinancialPoint) | X = `Date.Ticks`, plus `High`, `Open`, `Close` and `Low` | financial series |
| [FinancialPointI]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.FinancialPointI) | X = index, plus `High`, `Open`, `Close` and `Low` | financial series |
| [RangeValue]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.RangeValue) | X = index, from `Low` to `High` | range series |
| [BoxValue]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.BoxValue) | X = index, plus `Max`, `ThirdQuartile`, `FirtQuartile`, `Min` and `Median` | box series |
| [ErrorValue]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ErrorValue) | X = index, Y = `Y`, with a Y error | error bars |
| [ErrorPoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ErrorPoint) | X = `X`, Y = `Y`, with X and Y errors | error bars |
| [ErrorDateTimePoint]({{ website_url }}/api/{{ version }}/LiveChartsCore.Defaults.ErrorDateTimePoint) | X = `DateTime.Ticks`, Y = `Y`, with X and Y errors | error bars |

A `null` value is an [empty point](#empty-points), and so is a value of these types with a `null` coordinate property,
except `Weight`: a `null` weight counts as `0`.
`DateTimePoint`, `TimeSpanPoint` and `FinancialPoint` place the X in ticks; to show those ticks as dates or times on
the axis, see
[time and logarithmic scales]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Time%20and%20logarithmic%20scales).
The series articles show these types in use:
[financial]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Financial%20series),
[range]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Range%20series),
[box and error bars]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Box%20series%20and%20error%20bars),
[scatter and bubble]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Scatter%20and%20bubble%20series),
[heat]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Heat%20series) and
[polar]({{ website_url }}/docs/{{ platform }}/{{ version }}/PolarChart.Polar%20charts).

## The Mapping property

Imagine a JSON file with the temperature of a CPU at a given time:

```json
[
  { "Time": 1, "Temperature": 65.65, "Unit": "Celsius" },
  { "Time": 5, "Temperature": 62.23, "Unit": "Celsius" },
  { "Time": 8, "Temperature": 85.12, "Unit": "Celsius" }
]
```

deserialized to an array of `TempSample`:

```csharp
public record TempSample(int Time, double Temperature, string Unit);
```

LiveCharts does not know how to plot a `TempSample`: a series of this type throws an exception when the chart draws
it. The `Mapping` property of the series is a function that takes each value and its index in the `Values`
collection, and returns its `Coordinate`:

```csharp
using var streamReader = new StreamReader("data.json");
var samples = JsonSerializer.Deserialize<TempSample[]>(streamReader.ReadToEnd());

var chart = new SKCartesianChart
{
    Width = 900,
    Height = 600,
    Series = new[]
    {
        new LineSeries<TempSample>
        {
            Values = samples,
            // use the Time property as X // mark
            // and the Temperature property as Y // mark
            Mapping = (sample, index) => new(sample.Time, sample.Temperature) // mark
        }
    },
    XAxes = new[] { new Axis { Labeler = value => $"{value} seconds" } },
    YAxes = new[] { new Axis { Labeler = value => $"{value} °C" } }
};

chart.SaveImage("chart.png");
```

The index counts every item, `null` items included, but a `null` item never reaches the mapper: it is an empty point.
When the values implement `IChartEntity`, as all the built-in types do, the series ignores `Mapping` and uses the
coordinate of the value.

## Global mappers

`HasMap` registers a mapper for a type in the whole application: every series of that type uses it.

```csharp
// ideally this code must be placed where your application starts
LiveCharts.Configure(config => config
    .UseDefaults() // mark
    .HasMap<TempSample>((sample, index) => new(sample.Time, sample.Temperature))); // mark
```

- There is one global mapper per type: registering a mapper for `TempSample` again replaces the previous one.
- When a series sets `Mapping`, it uses that mapper instead of the global one.
- The mappers of the numeric types are global mappers too. `UseDefaults` registers them, but only when no mapper is
  registered yet, so when you configure LiveCharts at startup call `UseDefaults` before `HasMap`, as above.
- When a type has no mapper and does not implement `IChartEntity`, the chart throws an exception.

In XAML the series must know the type of its values. The XAML parser of this platform does not take generic types,
so declare a non-generic class that inherits from the XAML series with your type, and use that class in the view:

```csharp
public class TempSampleLineSeries : XamlLineSeries<TempSample> { }
```
{{~ else if avalonia || maui ~}}

In XAML the series must know the type of its values, set it with the `x:TypeArguments` attribute of the series, for
example `x:TypeArguments="vms:TempSample"`.

## The Coordinate struct

A `Coordinate` stores up to six values. `PrimaryValue` is normally the Y (the value on the X axis in a row series, the
radius in a polar series and the size of the slice in a pie), and `SecondaryValue` is normally the X (the angle in a
polar series). Each constructor fills them for a kind of series:

| Constructor | Used by |
|---|---|
| `new Coordinate(x, y)` | most series |
| `new Coordinate(x, y, weight)` | bubble and heat series, the weight is the `TertiaryValue` |
| `new Coordinate(x, high, open, close, low)` | financial series |
| `new Coordinate(x, max, thirdQuartile, firstQuartile, min, median)` | box series |
| `new Coordinate(primary, secondary, tertiary, quaternary, quinary, senary, error)` | sets every value, and the error of error bars |
| `Coordinate.Empty` | an [empty point](#empty-points) |

For example, the mappers of a financial type and of a range type:

```csharp
// a type with Date, High, Open, Close and Low properties
Mapping = (sample, index) => new(sample.Date.Ticks, sample.High, sample.Open, sample.Close, sample.Low)

// a range series takes the high as the primary value and the low as the tertiary value
Mapping = (sample, index) => new(sample.High, index, sample.Low, 0, 0, 0, Error.Empty)
```

## IChartEntity

A mapper runs for every value each time the series reads its values. A type that implements `IChartEntity` stores its
own coordinate and updates it only when its data changes, which performs better on large data sets. The interface
has two properties: the `Coordinate`, and the `MetaData`, information LiveCharts keeps about the point.

This `TempSample` uses the [CommunityToolkit.Mvvm](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/mvvm/)
to implement `INotifyPropertyChanged`, so the chart also updates when `Time` or `Temperature` change. LiveCharts does
not require `INotifyPropertyChanged`.

```csharp
public partial class TempSample : ObservableObject, IChartEntity
{
    [ObservableProperty]
    private int _time;

    [ObservableProperty]
    private double _temperature;

    public Coordinate Coordinate { get; protected set; } // mark

    public ChartEntityMetaData? MetaData { get; set; } // mark

    protected override void OnPropertyChanged(PropertyChangedEventArgs e) // mark
    { // mark
        Coordinate = new(Time, Temperature); // mark
        base.OnPropertyChanged(e); // mark
    } // mark
}
```

When the coordinate uses the index of the value, the type needs to know that index: LiveCharts sets
`MetaData.EntityIndex` when it reads the values, and calls the callback passed to the `ChartEntityMetaData`
constructor when the index changes. The built-in types such as `ObservableValue` work this way:

```csharp
public partial class City : ObservableObject, IChartEntity
{
    [ObservableProperty]
    private double _population;

    public City()
    {
        MetaData = new ChartEntityMetaData(OnCoordinateChanged); // mark
    }

    public Coordinate Coordinate { get; set; }

    public ChartEntityMetaData? MetaData { get; set; }

    protected override void OnPropertyChanged(PropertyChangedEventArgs e)
    {
        if (MetaData is not null) OnCoordinateChanged(MetaData.EntityIndex);
        base.OnPropertyChanged(e);
    }

    private void OnCoordinateChanged(int index) => // mark
        Coordinate = new(index, Population); // mark
}
```

A type that implements `IChartEntity` never uses a mapper, neither the `Mapping` of the series nor a global one.

## Empty points

A `null` value, or a coordinate that is `Coordinate.Empty`, is an empty point: it is not drawn, the axis limits skip
it, and a line breaks there:

![image](https://raw.githubusercontent.com/beto-rodriguez/LiveCharts2/master/docs/_assets/gaps.png)

```csharp
Series = new ISeries[]
{
    new ColumnSeries<double?>
    {
        Values = new double?[] { 5, 4, null, 3, 2, 6, 5, 6, 2 }
    },

    new LineSeries<double?>
    {
        Values = new double?[] { 2, 6, 5, 3, null, 5, 2, 4, null }
    },

    new LineSeries<ObservablePoint?>
    {
        Values = new ObservablePoint?[]
        {
            new ObservablePoint { X = 0, Y = 1 },
            new ObservablePoint { X = 1, Y = 4 },
            null,
            new ObservablePoint { X = 4, Y = 5 },
            new ObservablePoint { X = 6, Y = 1 },
            new ObservablePoint { X = 8, Y = 6 },
        }
    }
};
```

A mapper or an `IChartEntity` returns `Coordinate.Empty` to skip a value, for example a city with no population:

```csharp
using LiveChartsCore.Kernel;

public record City(string Name, double? Population);

Series = new ISeries[]
{
    new LineSeries<City>
    {
        Values = new City[]
        {
            new("London", 10),
            new("Paris", 8),
            new("Rome", null),
            new("Berlin", 7),
        },
        Mapping = (city, index) =>
            city.Population is null
                ? Coordinate.Empty // mark
                : new Coordinate(index, city.Population.Value)
    }
};
```

## NaN and Infinity

A coordinate whose X or Y is `double.NaN` is empty, like a `null` value. This applies to plain numbers, the built-in
types, mappers and `IChartEntity` types alike, because all of them build a `Coordinate`. In a `WeightedPoint` a `NaN`
weight counts as no weight (`0`), and in a `RangeValue` a `NaN` low makes the point empty.

`double.PositiveInfinity` and `double.NegativeInfinity` are not converted: an infinite value reaches the axis limits
as it is (see [issue #1847](https://github.com/Live-Charts/LiveCharts2/issues/1847)). How to show it depends on your
data, so map it yourself. Two common choices:

- **Treat it as missing.** Return `Coordinate.Empty`. The point is not drawn and has no tooltip, like a `null` value.
- **Keep it visible.** Return a coordinate such as `new Coordinate(index, 0)`: a column becomes a stub that still
  shows its tooltip, and a `YToolTipLabelFormatter` prints `"+∞"`, `"-∞"` or `"NaN"` from the original value. See
  the [tooltips article]({{ website_url }}/docs/{{ platform }}/{{ version }}/CartesianChart.Tooltips%20and%20crosshairs)
  for more about formatters.

With a mapper on the series:

```csharp
using LiveChartsCore.Kernel;
using LiveChartsCore.SkiaSharpView;

new ColumnSeries<double>
{
    Values = values,

    // treat it as missing:
    // Mapping = (value, index) =>
    //     double.IsInfinity(value)
    //         ? Coordinate.Empty
    //         : new Coordinate(index, value),

    // keep it visible:
    Mapping = (value, index) =>
        double.IsNaN(value) || double.IsInfinity(value)
            ? new Coordinate(index, 0)
            : new Coordinate(index, value),

    // print the original value in the tooltip
    YToolTipLabelFormatter = p =>
        double.IsPositiveInfinity(p.Model) ? "+∞"
        : double.IsNegativeInfinity(p.Model) ? "-∞"
        : double.IsNaN(p.Model) ? "NaN"
        : p.Model.ToString()
}
```

Or globally, for every series of `double`:

```csharp
LiveCharts.Configure(config => config
    .UseDefaults()
    .HasMap<double>((value, index) =>
        double.IsInfinity(value)
            ? Coordinate.Empty // or new Coordinate(index, 0)
            : new Coordinate(index, value)));
```

An `IChartEntity` type applies the same logic where it builds its coordinate:

```csharp
using System.ComponentModel;
using System.Runtime.CompilerServices;
using LiveChartsCore.Kernel;

public class SafeValue : IChartEntity, INotifyPropertyChanged
{
    public SafeValue() => MetaData = new ChartEntityMetaData(OnCoordinateChanged);
    public SafeValue(double value) : this() => Value = value;

    public double Value { get; set { field = value; OnPropertyChanged(); } }

    public ChartEntityMetaData? MetaData { get; set; }
    public Coordinate Coordinate { get; set; } = Coordinate.Empty;

    public event PropertyChangedEventHandler? PropertyChanged;

    private void OnPropertyChanged([CallerMemberName] string? propertyName = null)
    {
        if (MetaData is not null) OnCoordinateChanged(MetaData.EntityIndex);
        PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
    }

    private void OnCoordinateChanged(int index)
    {
        Coordinate = double.IsNaN(Value) || double.IsInfinity(Value)
            // ? Coordinate.Empty // treat it as missing
            ? new Coordinate(index, 0) // keep it visible
            : new Coordinate(index, Value);
    }
}
```

To keep it visible, set the `YToolTipLabelFormatter` of the series to format `p.Model.Value` as in the mapper above.

## Customize visuals

The coordinate places a point; the `PointMeasured` event changes how it looks. The series raises it every time it
measures a point (when the chart loads, resizes or the data changes) and gives access to the data (`Model`) and to
the shape drawn for the point (`Visual`). `PointCreated` runs once, when the shape of the point is created.

This sample plots a column series of `int` values and handles `PointMeasured` (the `PointMeasuredCommand` of the
series in the XAML samples) to set the `Fill` of each column from a list of four paints, picked by the index of the
